proposals for normal code/security review. Names belonging to
upstream applications and vendors remain their real names (Open WebUI, Hermes,
Ollama, Tailscale, RunPod); platform-owned resource names use Haven. No product,
account or credential value is inferred from a spelling alone.

## Worker integration review

At the pinned worker SHA, `runpod/start.sh` owns mesh startup, optional SSH key
injection, vLLM loopback bind, readiness probe, GPU watchdog and model caches.
Keep `RUNPOD_*`, `VLLM_*`, `TAILSCALE_AUTH_KEY`, `PUBLIC_KEY`, `TS_HOSTNAME`,
`/v1/models`, streaming completions and model-name semantics unchanged. These
are vendor/application contracts, not legacy platform branding.

The script's log says tailnet access is available, but source binds vLLM to
loopback and does not itself prove a working inbound tailnet forwarding path.
Do not infer deployed reachability or security from the README. Preserve accepted
integration evidence; a changed hostname/transport/publication boundary requires
specific sanitized runtime evidence through the approved private route.

No worker-side modification is in scope or required for acceptance. Any desired
worker rename/change is a separate optional future proposal requiring owner approval.
The historical two-repository inventory is evidence only. Do not change the deployed
worker or infer a need for fresh RunPod testing from branding.

## Delivery and exclusions

Group these mappings into the three PRs in the identity README. Reuse ADR-0006's
transaction, locks, backups and recovery; no generalized migration/copy framework.
Use existing verification with changed-boundary assertions and an exact reviewed
operator cleanup checklist. Production execution/activation/cleanup remain separate
owner decisions; authorized implementation PR preparation needs no new permission.
