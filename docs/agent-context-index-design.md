## 2. The question

Can an agent find the same answers while reading fewer generated bytes, without
losing discoverability for security-critical or non-code material, and without
weakening validation?

Two structural options were compared against the current layout:

* **A. one selective index** — a single `CODE_INDEX.md`-shaped file at the same
  24576 budget, carrying every indexed file with its full pinned symbol list,
  grouped by component, plus per-component counts.
* **B. manifest plus component indexes** — a small root manifest that says which
  component index to open, with one index file per component leaf. Two variants
  were measured: `B` (manifest lists component leaves and their sizes only) and
  `B2` (hybrid: the manifest also carries the full tracked-path list).
* **Baseline** — today's `REPO_MAP.md` + `CODE_INDEX.md`, for the same tasks.

`B2` exists because `B` could not route to non-code files at all. That was an
evidenced failure, not a preference; it is reported in section 3.4 rather than
hidden.

## 3. Measurements

All numbers are bytes of real files on disk at the verified base, and real line
ranges of real files. No number is a token count. Routes are replay models: the
harness opened the named files and counted their bytes, but the sequence of
reads is a modelled agent route, not an observed session. No agent telemetry
exists in this repository, so nothing here measures real agent behaviour.

### 3.1 Method and accounting rules

* Identical four queries for all four layouts; identical source targets.
* A read is `(path, 1-based line range)` or `(path, whole)`.
* **Dedupe:** a second read of the same `(path, range)` is recorded as a repeat
  and adds zero bytes. Two different ranges of one file are two reads.
* **Files read** counts distinct paths opened, not read steps.
* Index bytes and source bytes are reported separately, so a saving cannot come
  from silently skipping the source that grounds an answer.
* Repeated reads in these four routes: **0**. Dedupe therefore changes no
  total here; the rule is defined so a reviewer can model a route with re-reads.
* Answers were grounded by printing the matching source lines from the files
  the route opened. All four answers below were reached in all four layouts.
  The generator and candidate outputs were inspected while building the
  harness; Q4 was added *after* noticing that both candidates omit non-code
  files. That is disclosed, and Q4 is kept as a reported result, not removed.

Three observations that matter more than the totals:

1. **Source bytes dominate when the answer is in one big file.** `scripts/reset-passwords.sh`

2. **Indirection costs file reads.** B and B2 need two index opens per query

   a cost of 4858 bytes of manifest over B.

### 3.5 Verdict, stated plainly

The evidence supports **B2 only if** routing to non-code files is a requirement;
it supports **B** for code-only tasks; it does **not** support A, which pays most
of the baseline read for little gain and cannot route to the runbook. None of
the three is a drop-in: each loses or adds a behaviour the current pair has.

The measured problem B/B2 solves is the 30449-byte mandatory read on every task,
4.5% of which is the manifest. The measured problem B/B2 creates is one extra
index open per query and a new failure mode — an agent that reads the manifest
and stops has strictly less information than an agent that read `REPO_MAP.md`.

## 4. Inclusion and routing rules (non-negotiable in any implementation)

These preserve the security-critical discoverability that the current pair
provides. Each one is a testable assertion, not an intention.

1. **Tracked only.** Discovery is `git ls-files`. Untracked, ignored and
   generated-at-runtime files never appear.
2. **Secret, key, log and dump exclusions stay exactly as pinned:**
   `.git` directories, `.env` and `.env.*` except `.env.example`, `*.pem`,
   `*.key`, `*.log`, `id_*`, `CONSOLIDATED_*.md`, and the generated files
   themselves. No new exclusion, no removal.
3. **Symlinks and escaping paths are skipped** by metadata only (`os.lstat`,
   `realpath`), so a tracked symlink cannot leak content from outside the tree.
   Binary files are skipped by NUL sniff, never by extension guess.
4. **Deterministic output.** No timestamps, no commit SHAs, no absolute paths.
   Byte-identical for the same tracked tree. Two runs must hash equal.
5. **Explicit size enforcement, fail closed.** Every generated file is checked
   against the cap after writing; overflow exits non-zero naming the file and
   its size. **No truncation, no silent omission, no compression.** If content
   cannot fit, the run fails and the owner decides — the generator never guesses.
6. **No restructuring of source to fit a doc budget.** Comments are not stripped,
   files are not split, docstrings are not shortened to buy index bytes.
7. **Byte-for-byte freshness.** The checker compares generated bytes with
   committed bytes; it does not accept "semantically equivalent".
8. **Security-critical material is always reachable.** `SECURITY.md`,
   `SECURITY_SUMMARY.md`, `.github/workflows/sast-checks.yml`,
   `.github/workflows/agent-context.yml`, `openhands/AGENTS.md` and every
   workflow that gates `main` must be reachable from the initial read plus at
   most one deterministic routing step. If a layout makes any of them
   reachable only by guessing, the layout is rejected.
9. **Independent review.** Maps still land only through a reviewed pull request,
   except for the existing committer path, which is itself reviewed code.
10. **Routing is mechanical.** A component index is chosen by the tracked path
    of the file named in the task, not by free-form semantic search. Nothing in
    the routing table is hand-curated per task.

Rule 8 is the one the current pair satisfies trivially: `REPO_MAP.md` lists
every tracked path, including the security documents. B does not satisfy it for
non-code paths; B2 does, by carrying the path list.

## 5. Compatibility and staged migration

Nothing here is implemented. This section states what a future change would
have to do, so the owner can budget it before anyone writes code.

### 5.1 What has to change together

| Surface | Baseline assumption | Required change |
|---|---|---|
| Generator (pinned, other repo) | writes exactly two fixed filenames | new mode or new generator; the pin moves, and the pin is owned by `shared-actions` |
| `scripts/check-agent-context.sh` | `for name in REPO_MAP.md CODE_INDEX.md`, two `cmp`s | accept the new file set, or compare a directory tree |
| `scripts/test-check-agent-context.sh` | case 5 removes `REPO_MAP.md` | add cases for manifest-only and manifest-plus-leaves |
| `agent-context.yml` | pin `ref:` and the two script calls | new pin; unchanged scripts if the file set is unchanged |
| `agent-context-committer.yml` | loop guard, no-op guard, `git add`, PR body — four filename lists | all four, plus the staging list, must name the new set; a partial change silently creates an empty refresh PR |
| `openhands/AGENTS.md:15` | unconditional read of both maps | routing-aware instruction, or it points at files that no longer exist |
| `README.md`, `.github/CICD.md` | describe two files and one budget | describe the new set and the same budget |

The committer is the dangerous one. Its loop guard treats a push containing
only map files as its own refresh. If the new file set is not in that guard,
the committer will fire on its own merge and open a second refresh PR. If the
new file set is in the guard but not in `git add`, the refresh PR is empty.

### 5.2 Staged sequence (proposal, not executed)

1. Land the new generator mode in `shared-actions` and pin it. The old mode
   stays available.
2. In `hybrid-ai`, add the new files alongside the old pair, leaving the checker
   and committer untouched. Both sets are generated and both are fresh. Cost:
   the repository carries about 58 KB of generated context for one cycle
   (30449 current plus 27809 for B2).
3. Switch the checker to the new set, keeping a one-release window that also
   verifies the old pair.
4. Switch the committer's four filename lists and staging list in one commit.
5. Switch `openhands/AGENTS.md` and the two README sections.
6. Remove the old pair in a separate reviewed PR, only after an agent has
   actually navigated with the new layout.

Step 2 is the point of the sequence: it makes the migration reversible with a
revert of one commit, not a coordinated rollback across two repositories.

### 5.3 Rollback

Every step above is a single commit that only changes which generated files are
tracked and which list the checker reads. Rollback is `git revert` of that
commit plus a regeneration run; the generator pin is unchanged within a step,
so the maps stay reproducible. No data, no deploy and no runtime state is
involved.

### 5.4 Owner decisions

1. **Is routing to non-code files a requirement?** Yes → B2, or A plus a
   separate path listing. No → B.
2. **Is a second index open per task acceptable?** B and B2 both add one.
3. **Who owns the generator change?** It lives in `shared-actions`, not here.
   This repository can only consume a new mode.
4. **Does the budget stay 24576?** All three candidates fit, but A leaves only
   2826 bytes of headroom; a bigger `scripts/` file breaks it.
5. **Should the committer keep auto-merging refreshes?** A larger file set makes
   the committer's blast radius larger.
6. **What replaces the unconditional read** in `openhands/AGENTS.md:15`, and
   does the operator entry point at `openhands/README.md:246` need the same edit?

### 5.5 Future boundaries

Out of scope for any first change: semantic search, embeddings, per-task
summaries, cross-repository indexes, and any format that is not derived from
`git ls-files`. Also out of scope: changing the pin, the budget, the exclusion
list, or the committer's merge authority.

current 30449-byte pair and becomes cheaper still with a 1379-byte manifest, but
the duplication above means an agent may read the same rule from two places

context cost. It is out of scope for this change.

```python
#!/usr/bin/env python3
"""Scratch-only candidate context layouts (design evidence, not shipped).

Both layouts are built on the PINNED shared-actions generator
(3156ad16725e149a9baebeb71862a8d1d341418c), loaded as a module, so the
inclusion, exclusion, symlink, binary and description rules stay the reviewed
ones. Nothing is truncated: a file or leaf that cannot fit the cap fails.

    --mode single     one selective CODE_INDEX.md: full pinned symbol list per
                      indexed file, grouped by component, plus routing counts.
    --mode manifest   a small AGENT_CONTEXT.md manifest plus one index per
                      component leaf under agent-context/.

Selection is derived mechanically from `git ls-files` (tracked files only).
Point --generator at the pinned generate.py checked out at that revision.
"""

import argparse
import hashlib
import importlib.util
import os
import sys

HEADER = (
    "<!-- Generated by the agent-context candidate generator.\n"
    "     Source: `git ls-files` output. Do not edit by hand.\n"
    "     No timestamps or commit SHAs are included; output is deterministic. -->"
)


def load_pinned(path):
    spec = importlib.util.spec_from_file_location("pinned_agent_context", path)
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    return module


def collect(gen, root):
    """Return (paths, code_entries, skipped) using the pinned rules."""
    paths, code_entries, skipped = [], [], []
    for rel in gen.list_tracked_files(root):
        if gen.is_excluded(rel) or gen.is_unsafe_path(root, rel):
            skipped.append((rel, "excluded"))
            continue
        text = gen.read_text(os.path.join(root, rel))
        if text is None:
            skipped.append((rel, "unreadable-or-binary"))
            continue
        paths.append(rel)
        try:
            is_code = gen.index_text_file(rel, text) is not None
        except Exception:
            is_code = True
        if is_code:
            code_entries.append((rel, text))
        else:
            skipped.append((rel, "not-code"))
    return paths, code_entries, skipped


def component_of(rel_path):
    return rel_path.split("/")[0] if "/" in rel_path else "."


def leaf_of(rel_path, depth=2):
    parts = rel_path.split("/")
    if len(parts) <= 1:
        return "."
    return "/".join(parts[:depth]) if len(parts) > depth else parts[0]


def leaf_file(leaf):
    return "root.md" if leaf == "." else leaf.replace("/", "__") + ".md"


def check_cap(path, cap):
    size = os.path.getsize(path)
    if size > cap:
        sys.stderr.write("error: %s is %d bytes, cap is %d\n" % (path, size, cap))
        raise SystemExit(1)
    return size


def digest(path):
    with open(path, "rb") as handle:
        return hashlib.sha256(handle.read()).hexdigest()


def symbol_lines(gen, rel, text):
    try:
        return gen.index_text_file(rel, text)
    except Exception:
        return None


def write_mode_single(gen, root, out_dir, cap):
    paths, code_entries, skipped = collect(gen, root)
    by_component = {}
    for rel, text in code_entries:
        by_component.setdefault(component_of(rel), []).append((rel, text))
    lines = ["# Selective code index", "", HEADER, "", "## Component routing", ""]
    for comp in sorted(by_component):
        lines.append("- %s: %d indexed file(s)" % (comp, len(by_component[comp])))
    lines.append("")
    lines.append("%d analysable tracked path(s); %d indexed; %d non-code; "
                 "%d excluded by rule."
                 % (len(paths), len(code_entries),
                    len([1 for _, why in skipped if why == "not-code"]),
                    len([1 for _, why in skipped if why == "excluded"])))
    lines.append("")
    for comp in sorted(by_component):
        lines.append("## %s" % comp)
        lines.append("")
        for rel, text in sorted(by_component[comp]):
            symbols = symbol_lines(gen, rel, text)
            lines.append("### %s" % rel)
            if symbols is None:
                lines.append("- (unparsed)")
            elif not symbols:
                lines.append("- (no symbols)")
            else:
                lines.extend(symbols)
            lines.append("")
    out = os.path.join(out_dir, "CODE_INDEX.md")
    with open(out, "w", encoding="utf-8") as handle:
        handle.write("\n".join(lines))
    return out


def write_mode_manifest(gen, root, out_dir, cap, leaf_cap, include_paths=False):
    paths, code_entries, skipped = collect(gen, root)
    pending = {}
    for rel, text in code_entries:
        pending.setdefault(leaf_of(rel), []).append((rel, text))
    final = {}
    while pending:
        leaf, entries = pending.popitem()
        body = ["## %s" % leaf, ""]
        for rel, text in sorted(entries):
            symbols = symbol_lines(gen, rel, text)
            body.append("### %s" % rel)
            body.extend(symbols if symbols else ["- (no symbols)"])
            body.append("")
        if len("\n".join(body).encode("utf-8")) <= leaf_cap:
            final[leaf] = body
            continue
        depth = leaf.count("/") + 1
        deeper = {}
        for rel, text in entries:
            parts = rel.split("/")
            sub = "/".join(parts[: depth + 1]) if len(parts) > depth + 1 else leaf
            deeper.setdefault(sub, []).append((rel, text))
        if len(deeper) <= 1:
            sys.stderr.write("error: leaf %s cannot be split below the cap\n" % leaf)
            raise SystemExit(1)
        pending.update(deeper)
    index_dir = os.path.join(out_dir, "agent-context")
    os.makedirs(index_dir, exist_ok=True)
    rows = []
    for leaf in sorted(final):
        name = leaf_file(leaf)
        path = os.path.join(index_dir, name)
        with open(path, "w", encoding="utf-8") as handle:
            handle.write("# Index: %s\n\n%s\n" % (leaf, "\n".join(final[leaf])))
        rows.append((leaf, name,
                     len([line for line in final[leaf] if line.startswith("### ")]),
                     check_cap(path, cap)))
    manifest = ["# Agent context manifest", "", HEADER, "",
                "Read this file first. Open exactly one component index, and only",
                "when the task touches that component. Every tracked path is listed",
                "by `git ls-files`; the indexes cover code files only.", "",
                "| Component leaf | Index file | Files | Bytes |", "|---|---|---|---|"]
    for leaf, name, files, size in rows:
        manifest.append("| %s | agent-context/%s | %d | %d |" % (leaf, name, files, size))
    manifest.append("")
    manifest.append("%d analysable tracked path(s); %d indexed; %d non-code; "
                    "%d excluded by rule."
                    % (len(paths), len(code_entries),
                       len([1 for _, why in skipped if why == "not-code"]),
                       len([1 for _, why in skipped if why == "excluded"])))
    manifest.append("")
    if include_paths:
        manifest.append("## All tracked paths")
        manifest.append("")
        manifest.extend("- %s" % rel for rel in paths)
        manifest.append("")
    out = os.path.join(out_dir, "AGENT_CONTEXT.md")
    with open(out, "w", encoding="utf-8") as handle:
        handle.write("\n".join(manifest))
    return out, rows


def main(argv=None):
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--mode", choices=("single", "manifest"), required=True)
    parser.add_argument("--root", default=".")
    parser.add_argument("--output-dir", required=True)
    parser.add_argument("--generator", required=True, help="pinned generate.py at 3156ad1")
    parser.add_argument("--max-bytes", type=int, default=24576)
    parser.add_argument("--leaf-max-bytes", type=int, default=16384)
    parser.add_argument("--include-paths", action="store_true",
                        help="manifest mode: append the tracked-path list")
    args = parser.parse_args(argv)
    os.makedirs(args.output_dir, exist_ok=True)
    gen = load_pinned(args.generator)
    root = os.path.abspath(args.root)
    if args.mode == "single":
        out = write_mode_single(gen, root, args.output_dir, args.max_bytes)
        print("%s %d %s" % (out, check_cap(out, args.max_bytes), digest(out)))
        return 0
    out, rows = write_mode_manifest(gen, root, args.output_dir, args.max_bytes,
                                    args.leaf_max_bytes, args.include_paths)
    print("%s %d %s" % (out, check_cap(out, args.max_bytes), digest(out)))
    for leaf, name, files, size in rows:
        path = os.path.join(args.output_dir, "agent-context", name)
        print("%s %d %s" % (path, size, digest(path)))
    return 0


if __name__ == "__main__":
    sys.exit(main())
```
