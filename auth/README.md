# Forward-auth login service

A small, self-contained forward-auth endpoint for Caddy (`forward_auth`).
It is inert by default: nothing in this directory publishes a port or
changes any existing service. Wiring it into compose and the Caddyfile is a
separate change.

Python 3 standard library plus `bcrypt`, pinned exactly to `bcrypt==4.2.1`
in `auth/Dockerfile`. The same pin appears once on the test side, in
`auth/requirements-test.txt`.

## Endpoints

| Method | Path | Behaviour |
| --- | --- | --- |
| GET | `/healthz` | 200, no authentication. |
| GET | `/auth/login` | Login form. `next` is carried in a hidden input. |
| POST | `/auth/login` | Verifies credentials, sets the cookie, 302 to `next`. |
| GET | `/verify` | 200 on a valid cookie, otherwise 302 to the login form. |

## Environment

Names only. No value belongs in a tracked file.

| Variable | Required | Meaning |
| --- | --- | --- |
| `HYBRID_AI_AUTH_USER` | yes | The single allowed username. |
| `HYBRID_AI_AUTH_HASH` | yes | bcrypt hash of the password. Set it with `scripts/reset-passwords.sh`, which hashes inside this container at cost 12. |
| `HYBRID_AI_AUTH_COOKIE_SECRET` | yes | HMAC key for the cookie signature. Generated by `install.sh` when unset (a manual set is honoured). |
| `TLS_DOMAIN` | yes | Cookie `Domain` and the only allowed `next` host. |
| `HYBRID_AI_AUTH_COOKIE_MAX_AGE` | no | Cookie lifetime in seconds, default 86400. |
| `HYBRID_AI_AUTH_RATE_LIMIT` | no | Login attempts per source IP, default 5. |
| `HYBRID_AI_AUTH_RATE_WINDOW` | no | Window in seconds, default 60. |
| `PORT` | no | Default 8080. |
| `HOST` | no | Default is the container wildcard interface. |

Start-up is fail-closed: if any required variable is empty or whitespace the
process exits non-zero and names the variable it is missing. There is no
default credential and no development bypass.

## Rotating the password

Run [`../scripts/reset-passwords.sh`](../scripts/reset-passwords.sh) on the
host. It hashes the new password inside this container with `bcrypt` at cost
12, writes only the `HYBRID_AI_AUTH_HASH` line of the stack env file (escaped
for Compose, every other line byte-for-byte preserved), backs the file up at
mode 0600, recreates only the `auth` service, and verifies in-container that
the gate reads a 60-byte hash. `HYBRID_AI_AUTH_USER`, `AUTH_ENABLED` and
`HYBRID_AI_AUTH_COOKIE_SECRET` are not touched, so open sessions stay valid.

## Security notes

- `next` must be an absolute `https` URL whose host is `TLS_DOMAIN` or a
  subdomain of it. Anything else, including protocol-relative and
  `javascript:` values, falls back to `https://$TLS_DOMAIN/`.
- Every login failure returns the same 401 and the same body. Both the
  username comparison and the bcrypt check always run, so timing does not
  separate a wrong user from a wrong password.
- The cookie is `<exp>.<HMAC-SHA256 hex of exp>` keyed by
  `HYBRID_AI_AUTH_COOKIE_SECRET`, and is verified with a constant-time
  comparison. Cookie values are never logged and never echoed into errors.
- Login attempts are limited per source IP in memory.
- The container runs as a non-root user and listens on port 8080 inside the
  container only. The bind default is the wildcard interface inside the
  container; publish ports only through compose, if at all.

## Tests

```
python3 -m pip install -r auth/requirements-test.txt
python3 -m unittest discover -s auth -p 'test_*.py' -v
```

Everything runs offline over loopback: no Docker and no network.

## Docker health probe (#160)

The auth service inherits the Python probe in `auth/Dockerfile`: an
unauthenticated IPv4 loopback request to port 8080 at `/healthz`, with a
two-second request timeout. Docker runs it every 30 seconds, with a three-second
timeout, five-second start period and three retries. The standard deployment
uses the application's wildcard IPv4 bind and default port; no host port is
published. This probe does not depend on hostname resolution, IPv6 or `wget`.

Owner evidence on 2026-11-10 showed that the deployed Compose override instead
executed `wget` against a literal bracketed address placeholder at port 8080.
Docker recorded repeated exit code 1 with empty output (the command redirected
both output streams), while the owner's loopback `wget` and Python requests
succeeded with HTTP 200. The same placeholder appeared in the source template.
Removing that override restores the image probe rather than substituting a
host address. This fixes the evidenced probe target defect; it does not establish
that production has been repaired.

After separately approved merge and deployment, the owner should confirm the
effective health command is the image's Python probe and Docker reports healthy
after several probe intervals. Verify the health endpoint and normal gated
access; record only health status, exit codes and revision/image identity.
Do not share environment dumps, credentials or session cookies. Custom
`AUTH_IMAGE` images must supply an equivalent health check. Roll back through
the normal reviewed deployment process using the prior revision and image;
the old revision may restore this unhealthy probe. No live remediation is
performed by this source change.
